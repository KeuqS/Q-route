# Contributing to Q Route

Thank you for your interest in contributing to Q Route.

Q Route is an independent open-source project exploring privacy-aware safety technology for ride-hailing and campus transportation.

## Ways to contribute

You can contribute by:

- Reporting bugs.
- Suggesting improvements.
- Reviewing technical ideas.
- Improving documentation.
- Adding tests.
- Improving accessibility.
- Reviewing privacy and security concerns.
- Contributing code.
- Creating simulated ride scenarios.

## Before contributing

Please:

1. Read the `README.md`.
2. Read the `CODE_OF_CONDUCT.md`.
3. Read the `SECURITY.md` before reporting security issues.
4. Read the `PRIVACY.md` before working with location or personal data.
5. Search existing issues and pull requests before creating a new one.

## Issues

Use an issue to:

- Report a reproducible bug.
- Suggest a feature.
- Ask a technical question.
- Propose a documentation improvement.
- Discuss a design decision.

Include enough context for others to understand the issue.

For bug reports, include:

- What happened.
- What you expected to happen.
- Steps to reproduce it.
- Relevant logs or screenshots.
- Environment details.
- Whether the issue is reproducible.

Do not include real names, phone numbers, live locations, API keys, or other sensitive information.

## Pull requests

Before opening a pull request:

- Keep the change focused.
- Explain what was changed and why.
- Update relevant documentation.
- Add or update tests where appropriate.
- Check that no secrets or personal data are included.
- Confirm that the change does not make unsafe emergency-response claims.

Use a clear pull-request title and describe any known limitations.

## Development principles

Contributions should prioritize:

- User consent.
- Privacy.
- Security.
- Accessibility.
- Reliability.
- Low false-alarm rates.
- Clear documentation.
- Reproducible testing.

## Discussion

For significant architectural, privacy, or emergency-workflow changes, open an issue before implementing the change.

Maintainers may request changes, additional tests, or further discussion before accepting a contribution.
